# Pegarr v0.1.3

Pegarr v0.1.3 keeps active private-browser sessions usable without weakening the server-side authentication boundary.

## Fixed

- Signing in now creates a session that expires after 30 days without authenticated use instead of a fixed eight-hour session.
- Restoring Pegarr renews that bounded inactivity window and rotates the page-memory CSRF token.
- The opaque session remains in a host-only `HttpOnly`, `SameSite=Strict` cookie and only hashed session/CSRF state is stored in the private mode-`0600` database.
- Logout still deletes the durable session immediately.

## Acceptance

- Deterministic route and session-store coverage proves renewal, expiry, CSRF rotation, capacity bounds, and logout.
- The packaged container proves an authenticated session survives restart, renews on restore, never stores raw private material, and remains logged out after another restart.
- Installed Bazarr acceptance found 13 file-backed Radarr movies and confirmed a `PT-BR + English` assignment for movie ID `7`, closing the remaining live Bazarr policy gap without changing the library.

## Install

Pin the versioned image in Compose or Portainer:

```yaml
image: ghcr.io/squiter/pegarr:0.1.3
```

Preserve the existing `/data` volume and every Arr/Bazarr mount during the update. Existing unexpired sessions remain valid; their inactivity window renews after the first authenticated restore on this version.

## Remaining manual boundaries

- A successful OpenSubtitles response, rate evidence, live language mapping, and cache reuse remain open. Provider unavailability remains `Unknown`, never `No match found`.
- A harmless operator-owned controlled Grab and Unknown-outcome reconciliation remain manual and must never be automated against live services.
