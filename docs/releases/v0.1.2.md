# Pegarr v0.1.2

Pegarr v0.1.2 is a focused post-release continuation fix found during the installed Radarr acceptance cycle.

## Fixed

- **Refresh analysis** now reuses the server-owned post-add continuation route.
- Exact movie, season, and episode analysis therefore keeps the explicit Pegarr subtitle policy before a media file exists.
- The refresh no longer falls through to the ordinary missing-library route, where Bazarr honestly reports that a fileless Radarr movie is not in its subtitle library.

## Live acceptance

- The installed Radarr accepted **The Adventures of Tintin** as a monitored movie with automatic search disabled.
- Pegarr immediately evaluated 11 exact Radarr release candidates while keeping controlled Grab disabled.
- Radarr's queue remained empty and its history contained no title-scoped search or download activity.
- Bazarr's completed Radarr sync named the new title, but its movie inventory remained unchanged because Bazarr intentionally stores only movies that already have a video file. Pegarr's explicit pre-download policy remains authoritative for this stage.

## Install

Pin the versioned image in Compose or Portainer:

```yaml
image: ghcr.io/squiter/pegarr:0.1.2
```

Preserve the existing `/data` volume and every Arr/Bazarr mount during the update. Read-only remains the default; catalog add and controlled Grab are independent opt-ins.

## Remaining manual boundaries

- Installed Bazarr movie-assignment reads still need a file-backed Radarr movie acceptance case.
- Provider-secret file permissions still need a sanitized installed check.
- A successful OpenSubtitles response, rate evidence, mapping compatibility, and cache reuse remain open.
- A harmless operator-owned controlled Grab and Unknown-outcome reconciliation remain manual and must never be automated.
